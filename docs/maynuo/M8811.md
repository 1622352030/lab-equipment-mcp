## Electrical interface warning

The rear DB9 connector is a 5 V TTL serial interface. It is not a standard RS-232 port.
Do not connect it directly to a normal PC RS-232 port or a USB-to-RS-232 cable.

Supported paths documented by Maynuo:

| Path | Required conversion | Status |
| --- | --- | --- |
| USB/TTL | M133, or a verified compatible USB-TTL converter | Tested with CH340 auto-enumeration |
| RS-232 | M131 TTL-to-RS-232 cable, then a PC RS-232 adapter | Implemented, not tested |
| RS-485 | M132 TTL-to-RS-485 cable, then a two-wire RS-485 adapter | Implemented, not tested |

The hardware-tested compatible USB-TTL wiring was:

```text
USB-TTL TXD -> M8811 DB9 pin 2 (RXD)
USB-TTL RXD <- M8811 DB9 pin 3 (TXD)
USB-TTL GND -> M8811 DB9 pin 5 (GND)
```

DB9 pin 1 is the instrument's +5 V VCC pin. It was left disconnected during the CH340
test. A passive DB9 breakout may be used to expose pins, but an active RS-232 splitter or
level converter must not be mistaken for a passive breakout.

## Serial settings

- Default baud rate: 9600 (panel-selectable: 4800, 9600, 19200, or 38400).
- Data bits: 8.
- Stop bits: 1.
- Default parity: none (panel-selectable: none, even, or odd).
- Flow control: none.
- Every command ends with LF (`0x0A`).
- `m8811_connect` accepts `baud_rate=4800|9600|19200|38400` and
  `parity=none|even|odd`; these values configure the PC-side serial session and must match
  the front-panel settings.
- The MCP does not claim to remotely change the instrument's baud rate or parity. The manual
  documents them as panel settings, not SCPI commands.
- The MCP enumerates connected CH340/CH341 adapters through Windows PnP and intersects them
  with VISA ASRL resources. It auto-selects only when exactly one candidate is present.
- If multiple CH340/CH341 adapters are connected, pass the intended `ASRLx::INSTR` resource.

The tested Windows device enumerated as a WCH CH340 USB serial adapter and was exposed by
VISA as an ASRL resource. The assigned COM number and instrument serial number are
intentionally not recorded because the port assignment can change.

## Installation and device check

1. Connect the verified USB-TTL adapter to the rear DB9 using TX -> pin 2, RX -> pin 3,
   and GND -> pin 5. Leave pin 1 VCC disconnected when the adapter is independently powered.
2. Power on the M8811 and set its panel communication parameters. The tested configuration
   is 9600 baud, 8 data bits, no parity, one stop bit, and no flow control.
3. Install the adapter's Windows driver and a VISA runtime that exposes serial ports as
   `ASRLx::INSTR`. The tested adapter uses the WCH CH340/CH341 driver.
4. Install or refresh the MCP using the repository instructions, fully restart Codex Desktop,
   and create a new task so the updated tool list is loaded.
5. Call `m8811_diagnose_setup`. `ready: true` means a CH340/CH341 path, PyVISA, and a VISA
   runtime were found. Automatic connection is allowed only when one adapter is a candidate.
6. Call `m8811_connect` with serial settings matching the front panel, then use
   `m8811_identify` or `m8811_get_settings` before changing output state.

Example request:

```text
Diagnose the M8811 connection, automatically select it only if exactly one CH340/CH341
adapter is present, connect at 9600 baud with no parity, identify it with the serial number
redacted, read the settings, and keep output disabled.
```

## Firmware and hardware evidence

Hardware acceptance on 2026-07-28 identified:

- Manufacturer: MAYNUO.
- Model: M8811.
- Firmware: V2.6.
- Serial number: redacted.
- Read-only identity, output status, FIX mode, voltage/current/protection setpoints,
  `MEAS:VOLT?`, `MEAS:CURR?`, `MEAS:VCM?`, and `SYST:ERR?` responded successfully.
- Output was OFF and the error queue returned `0,'No Error'` during the initial test.
- Automatic CH340/CH341 discovery, 5 V/0.1 A/30 V-protection setting writes, and typed
  read-back were then tested while output remained OFF.
- The firmware initially reported stored internal settings of 31 V, 5.1 A, and 31 V
  protection. These exceed the M8811 nameplate ratings. Acceptance intentionally restored
  the safe rated maxima of 30 V, 5 A, and 30 V instead of writing the over-rated values back.
- A later two-wire output test used a nominal 200 ohm power resistor. In FIX mode, a 1.000 V,
  0.100 A-limit setting measured 0.9985 V and 4.87 mA, equivalent to about 205 ohm including
  resistor tolerance and wiring. This is automated closed-loop evidence from the M8811's
  internal output voltage/current measurements.
- Sustained FIX tests held 5 V and 10 V for 20 seconds each with a 0.1 A current limit. Five
  samples at each level remained stable: 5 V measured 4.9999-5.0001 V and 24.85-24.87 mA;
  10 V measured 10.0006-10.0007 V and 49.86-49.88 mA. The corresponding nominal resistor
  powers were about 0.125 W and 0.5 W. Output was disabled for two seconds between levels.
- LIST mode was tested with two 500 ms LOOP steps at 1 V and 2 V. Stable samples measured
  about 0.999 V/4.9 mA and 1.999 V/9.9 mA. Transition samples were expected while switching.
  The original LIST partition, count, mode, and first two steps were restored afterward.
- Output-enable confirmation, raw-output blocking, compound-write blocking, nameplate limits,
  LIST capacity validation, DRM confirmation, panel-lock confirmation, LIST-recall
  confirmation, and amp-hour-clear confirmation were exercised successfully.
- On the tested V2.6 firmware, `MEAS:AHRD?` and `MEAS:DRM?` consistently timed out. The
  ordinary voltage/current/DVM/VCM measurements responded. DVM, DRM, and remote sense were
  not physically validated because only the main output and resistor were connected.

The FIX and LIST results are under-load evidence from the instrument's internal measurements,
not calibration-grade evidence from an independent meter. M131 and M132 paths, non-default
panel baud/parity settings, DVM input, DRM wiring, and four-wire remote sense remain untested.
Every output test ended with output OFF. The final restored state was FIX mode, 22 V setpoint,
5 A current limit, and 30 V protection.

## SCPI coverage

Typed MCP tools cover identity, settings, measurements, rated-range voltage/current/protection,
guarded output control, FIX/LIST/DRM selection, LIST editing/recall, remote sense, panel control,
and amp-hour clearing. `m8811_query_scpi` and `m8811_write_scpi` provide a model-prefixed entry
point for every applicable command documented on manual pages 25-31:

- `*IDN?`.
- `SYSTem:ERRor?`, `SYSTem:REM`, `SYSTem:LOC`, `SYSTem:SENSe`, `SYSTem:AHCL`.
- `MEASure:VOLTage?`, `CURRent?`, `DVM?`, `VCM?`, `AHRD?`, and `DRM?`.
- `OUTPut`, `MODE`, `VOLTage`, `CURRent`, and `VOLTage:PROTection` writes/queries.
- `LIST:AREA`, `RCL`, `COUNt`, `MODE`, `VOLTage`, `CURRent`, and `WIDTh`.
- `MODE DRM`, `DRM0`, `DRM1`, and `DRM2`.
- Optional RS-485 `$ddd` address frames.

Commands not listed in the M88 manual are rejected by the model-specific raw entry points.
Long and short SCPI mnemonics are accepted.

LIST memory contains 200 total steps. The typed LIST tools apply the manual's partition
relationship: 1 area allows 200 steps per area, 2 areas allow 100, 4 areas allow 50, and
8 areas allow 25. `m8811_configure_list`, `m8811_set_list_step`, and
`m8811_recall_list` validate against the current partition before writing.

## Safety behavior

- Typed voltage and current tools enforce the M8811 nameplate limits of 30 V and 5 A even
  though the tested firmware reported internal maxima of 31 V and 5.1 A.
- Voltage, current, protection, mode, LIST, and remote-sense changes require output OFF.
- Output enable requires `confirm_enable=true` and is verified using `OUTP?`.
- DRM can source resistance-test power and requires `confirm_drm=true`.
- Remote panel lock, LIST recall, and amp-hour clearing require explicit confirmation.
- Commands without a documented query return an explicit `unverified` result.
- Raw compound writes and raw state changes that could bypass typed validation are blocked.
  Use the corresponding typed tools and their explicit confirmation parameters.
- RS-485 broadcast and compound-write extensions are not exposed as MCP tools; the current
  implementation focuses on the actually used point-to-point connection path.
- `*IDN?` results returned through M8811 tools redact the hardware serial number.

## Common operations

Read the current state without enabling output:

```text
Connect to the M8811 through the unique CH340 adapter, read voltage/current/protection,
mode, and VCM measurement, and leave output disabled.
```

Configure a safe fixed output, with a separate confirmation before enabling it:

```text
With M8811 output off, set FIX mode, 5 V, 0.1 A current limit, and 30 V protection.
Read the values back, then ask me before enabling output.
```

Configure LIST while output remains off:

```text
Configure the M8811 LIST memory as two areas, use two LOOP steps at 1 V and 2 V with
0.1 A limits and 500 ms widths, verify every value, and do not enable output.
```

## Troubleshooting

- If no CH340/CH341 candidate appears, check Windows Device Manager, the adapter driver,
  USB cable/hub, and power. The MCP does not blindly probe unrelated COM ports.
- If diagnosis finds the adapter but VISA does not list it, ensure a VISA runtime is installed.
  The connection path can still open the bounded PnP-derived ASRL resource directly.
- If several CH340/CH341 adapters are connected, pass the intended `ASRLx::INSTR`
  explicitly. Do not document a fixed COM number because Windows may reassign it.
- If identity queries time out, verify that MCP `baud_rate` and `parity` match the panel and
  close serial terminals or vendor applications that may hold the port exclusively.
- If commands return parameter or invalid-command errors, call `SYSTem:ERRor?`, verify that
  output is OFF for protected settings, and prefer the typed M8811 tool over a raw write.
- On tested firmware V2.6, `MEAS:AHRD?` and `MEAS:DRM?` time out. This is recorded as a
  firmware behavior; it must not be reported as a successful measurement.
- Remote sense requires separate sense wiring, DRM requires its dedicated milliohm-test
  connection, and DVM requires its measurement input. Do not infer those paths from a load
  connected only to the main output terminals.

## Example acceptance prompt

```text
With a verified 200-ohm resistor on the M8811 main output, preserve the original state,
test low-power FIX and LIST levels, sample voltage/current during each hold, then disable
output and restore the original settings in a finally path. Do not test DVM, DRM, or remote

```
