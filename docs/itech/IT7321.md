# ITECH IT7321 Programmable AC Power Source

## Manual and scope

| Item | Value |
| --- | --- |
| Programming guide | IT7300 编程与语法指南 V3.2 (2018-03-15), part number IT7300-402211 |
| User manual | IT7300 用户手册 |
| Model coverage | The guides cover IT7321/7322/7322H/7324/7324H/7326/7326H and the "T" variants; this driver targets the **IT7321** |
| Rated output | **300 V / 3 A / 300 VA**, 45-500 Hz (user manual specification table) |
| Firmware seen | `0.16-0.22` (from `*IDN?`) |

The IT7321 is a single-phase programmable AC source. The programming guide is
the authority for the command set; the user manual carries the ratings, the
front-panel menus and the protection behaviour.

**The instrument can output 300 V.** Nothing in this driver may be relied on to
make high-voltage work safe - see the ceiling section below.

## Interface and session settings

| Item | Value |
| --- | --- |
| Interface | **LAN socket** (`TCPIP0::<ip>::30000::SOCKET`) |
| Default port | **30000** (`Socket Port` in the front-panel LAN menu) |
| Default address | `192.168.0.125` in the manual's example; the unit on this bench was set to that address with gateway `192.168.0.1` |
| Also fitted | USB and RS-232 (not used by this driver) |
| Terminator | Commands and replies end with `<NL>`; `<CR><LF>` is also accepted (programming guide 1.4, p4) |

The LAN settings are configured **from the front panel only**:
`Shift` + `Menu` → `System` → `Communication` → `LAN` → set Gateway / IP / Mask /
Socket Port. There is no documented command to read or change them over the bus.

### Protocol (verified on hardware)

Three facts cost real debugging time and are worth stating plainly.

**1. `SYSTem:REMote` must be sent before any control command.**

Programming guide p9: "没有先发送该命令进行远程控制配置就用 PC 机发送控制命令的话可能会引起通讯出错."
On firmware `0.16-0.22` the behaviour is stronger than "may cause errors": until
`SYST:REM` is sent, **queries answer normally but every set command is rejected**
with `-200,Execution error`. Verified directly - `VOLT 0` failed before remote
mode and succeeded immediately after it.

```text
before SYST:REM:  VOLT 0  -> (no reply), VOLT? -> 27.0, SYST:ERR? -> -200,Execution error
after  SYST:REM:  VOLT 0  -> (no reply), VOLT? -> 0.0,  SYST:ERR? -> 0,No error
```

`SYSTem:LOCal` releases the panel; the driver's `disconnect` also drops the
output first, so a locked panel is never left behind.

**2. The instrument is quiet on writes and needs settling time.**

A set command produces no reply. More importantly, **a read-back issued
immediately after a set can still return the old value**:

```text
OUTP 1 then immediately OUTP?   -> 0     (wrong)
OUTP 1 ... wait ~1 s ... OUTP?  -> 1     (correct)
```

The driver therefore waits (`settle_s`, default 0.35 s) before every read-back.
Without it, `set_output(True)` reported `enabled: False` while the output was in
fact on - a dangerous direction to be wrong in.

**3. Only one TCP session is accepted.**

A second `connect` while another client holds the socket is refused
(`WinError 10061`). This matters for the over-voltage guard: while it runs it
owns the socket, and nothing else may talk to the instrument.

### Errors and the beeper

`SYSTem:ERRor?` returns one entry per read, FIFO, up to 20 entries; an empty
queue answers `0,No error` (p8). **Every error also beeps once**, so a stream of
rejected commands is audible from across the room. `*RST` does **not** clear the
error queue - use `SYSTem:CLEar`.

## Output voltage ceiling (30 V) - read this first

The instrument is rated to **300 V**, but this integration is deliberately
capped at **30 V**. The user set that cap for the whole testing phase as a bound
on what a wrong command could do, and it may only be lifted with the user's
explicit agreement.

The cap is implemented in **three independent places**, and all three are
required:

| Layer | Mechanism | Verified evidence |
| --- | --- | --- |
| 1. Instrument | `CONF:VOLT:MAX 30` | `VOLT 45` → `120,Parameter overflowed`; setpoint unchanged |
| 2. Driver | `set_voltage()` refuses anything above the limit | `set_voltage(30.5/45/300)` rejected **and nothing sent to the wire** |
| 3. Pre-enable | `set_output(True)` reads back `VOLT?` **and** `CONF:VOLT:MAX?` and refuses if either exceeds the limit | enabling without `confirm_enable=True` refused; a setpoint or ceiling pushed out of range by someone else also blocks it |
| 4. Runtime | `scripts/it7321_voltage_guard.py` monitors the 8808A and cuts the output | live 10 V output with a 5 V threshold tripped in **52 ms** |

### How to change it (and why not to)

The ceiling is a **single constant** with an environment override - one edit, in
one place:

```python
# src/lab_equipment_mcp/devices/itech/it7321.py
IT7321_TEST_VOLTAGE_LIMIT_V = 30.0
```

or, without touching code:

```powershell
$env:LAB_EQUIPMENT_IT7321_MAX_VOLTAGE = "300"
```

`it7321_get_voltage_limit` reports the value in force and whether it came from
the environment. Two guards keep the layers consistent:

* the override may never exceed the instrument rating (300 V);
* `clamp_voltage_ceiling()` **refuses to raise the instrument's ceiling above
  the configured limit**, so you cannot end up with a driver limit of 30 V and an
  instrument ceiling of 300 V.

Raising this requires the user's agreement, and the device-side ceiling has to be
raised with it.

## Manual versus firmware

Measured on firmware `0.16-0.22`. Items marked "manual says" are what the
programming guide states.

| Item | Manual says | Hardware does | Handling |
| --- | --- | --- | --- |
| Control before `SYST:REM` | "may cause communication errors" (p9) | **Every set command is rejected** with `-200`; queries still work | `connect()` sends `SYST:REM` automatically |
| Write acknowledgement | Not described | Writes are silent; read-back immediately afterwards may return the **old** value | `settle_s` delay before every read-back |
| `VOLT:UNIT?` | Documented as queryable | **No reply at all** | Set-only; the guide notes it cannot be read back |
| `OUTP 1` / `OUTP:STAT 1` | `<bool>` `off\|on\|0\|1` | Both accepted, but only visible after the settling delay | Settle before reading |
| `CONF:VOLT:MAX` | Configuration limit | Enforced: a setpoint above it answers `120,Parameter overflowed` | Used as the hardware backstop |
| TCP sessions | Not stated | Only one accepted | Driver holds one; the guard owns it while running |
| Every error | "蜂鸣器将蜂鸣一次" (p8) | Confirmed - rejected commands are audible | `drain_errors()` clears them |

### Closed loop against the Fluke 8808A (2026-09-20)

IT7321 output → 8808A (`VΩ`/`LO`, VAC, fast). The agreement also settles what the
voltage unit is: **a 1:1 match means the setpoint is in RMS volts**, not
peak-to-peak (a VPP setpoint would have read about 1.77 V for a 5 V setting).

| **Set (V)** | **8808A (V)** | **Error (V)** | **Error (%)** |
| --- | --- | --- | --- |
| 5.0 | 5.0483 | +0.0483 | +0.97% |
| 10.0 | 10.0457 | +0.0457 | +0.46% |
| 20.0 | 20.0267 | +0.0267 | +0.13% |
| 30.0 | 30.0200 | +0.0200 | +0.07% |

Error shrinks as the setpoint rises; all points are within 1%, comfortably inside
the source's own accuracy specification.

### Over-voltage guard, tested while live

```
1) driver establishes a real output:  VOLT?=10.0  OUTP?=1
   then releases the socket (output stays on)
2) guard started with a 5 V threshold:
   [18:09:22.558] source  VOLT?=10.0 OUTP?=1 CONF:VOLT:MAX?=30
   [18:09:22.610] TRIP    over voltage: |10.0470| > 5.0 V
   [18:09:22.610] action  OUTP 0 sent (output off)
   [18:09:22.610] action  VOLT 0 sent (setpoint dropped)
3) afterwards:  VOLT? -> 0.0   OUTP? -> 0
```

**52 ms** from reading the over-voltage to cutting the output.

## Troubleshooting

| Symptom | Cause | Fix |
| --- | --- | --- |
| Set commands rejected with `-200,Execution error` | Not in remote mode | The driver sends `SYST:REM` on connect; send `it7321_set_remote` if it was returned to local |
| `WinError 10061` on connect | Another client holds the single TCP session | Close the other client (or the guard) first |
| Instrument beeps repeatedly | Every error beeps once | `it7321_get_errors` to drain, `it7321_clear_errors` to clear, `it7321_set_beeper(False)` to silence |
| Read-back shows the previous value | Read issued before the instrument settled | The driver's `settle_s` handles it; allow ~0.5 s if driving the socket by hand |
| `VOLT 45` accepted when it should not be | `CONF:VOLT:MAX` is still 300 | `it7321_clamp_voltage_ceiling()` to re-apply the 30 V ceiling |
| No route to `192.168.0.125` | PC has no address in that subnet | Add one, or move the instrument to the PC's subnet (front panel LAN menu) |
| Panel is unresponsive | Remote mode locks everything except Shift/Local/Select/On-Off | `it7321_set_local`, press `Local`, or `it7321_disconnect` |
