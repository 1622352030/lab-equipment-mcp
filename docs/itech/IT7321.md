# ITECH IT7321 可编程交流电源

## 手册与范围

| 项 | 内容 |
| --- | --- |
| 编程手册 | IT7300 编程与语法指南 V3.2（2018-03-15），手册部件号 IT7300-402211 |
| 用户手册 | IT7300 用户手册 |

| 实测固件 | `0.16-0.22`（来自 `*IDN?`） |

IT7321 是单相可编程交流电源。命令集以**编程手册**为准；额定值、前面板菜单和保护
行为以**用户手册**为准。

**这台设备可以输出 300 V。** 本驱动中的任何保护都不能被当作高压作业的安全依据，
详见下面的上限一节。

都通过 `default_host()` / `default_port()` / `default_resource()` 取值，
因此**换设备 IP 只需改上面那一行（或设一个环境变量）**。

### 协议（实机验证）

以下三条是实际调试中付出代价才确认的，值得单独列出。

**一、任何控制命令之前必须先发 `SYSTem:REMote`。**

编程手册第 9 页原文：「没有先发送该命令进行远程控制配置就用 PC 机发送控制命令的话
可能会引起通讯出错。」在固件 `0.16-0.22` 上，实际行为比「可能出错」更强：**未进入
远程模式时，查询正常应答，但所有设置命令一律被拒**，错误为 `-200,Execution error`。
实测对照：

```text
发 SYST:REM 之前：  VOLT 0 → 无应答， VOLT? → 27.0， SYST:ERR? → -200,Execution error
发 SYST:REM 之后：  VOLT 0 → 无应答， VOLT? → 0.0，  SYST:ERR? → 0,No error
```

`SYSTem:LOCal` 用于交还面板；驱动的 `disconnect` 会先关闭输出再交还，因此不会把
面板锁住就离开。

**二、设备对写命令不回话，而且需要等待时间。**

设置命令没有应答。更要紧的是：**写命令之后立即读回，可能读到的仍是旧值**：

```text
OUTP 1 之后立即 OUTP?   → 0     （错误）
OUTP 1 等待约 1 s 后 OUTP? → 1   （正确）
```

因此驱动在每次读回前都会等待（`settle_s`，默认 0.35 s）。没有这个等待时，
`set_output(True)` 会报告 `enabled: False`，而输出实际上**已经打开**——这个方向的
错误非常危险。

**三、只接受一个 TCP 会话。**

当已有客户端占用 socket 时，第二个 `connect` 会被拒绝（`WinError 10061`）。这直接
影响过压监控进程：它运行期间独占该 socket，其他程序无法同时与设备通信。

### 错误与蜂鸣器

`SYSTem:ERRor?` 每次读出一条错误，遵循先进先出，最多缓存 20 条；队列为空时返回
`0,No error`（第 8 页）。**每产生一条错误，蜂鸣器会响一声**，所以一连串被拒的命令
在房间里是听得见的。`*RST` **不会**清除错误队列，需要 `SYSTem:CLEar`。

## 输出电压上限（30 V）——请先读这一节

设备额定可输出 **300 V**，但本次集成**刻意限制在 30 V**。这是用户为整个测试阶段
设定的安全上限，用于约束错误指令可能造成的后果，**只有在用户明确同意后才能放开**。

该上限在**三个相互独立的位置**同时落实，缺一不可：

| 层 | 机制 | 验证证据 |
| --- | --- | --- |
| 一、设备侧 | `CONF:VOLT:MAX 30` | 故意发 `VOLT 45` → 设备回 **`120,Parameter overflowed`**，设定值不变 |
| 二、驱动侧 | `set_voltage()` 拒绝超限值 | `set_voltage(30.5/45/300)` 全部被拒，**且没有向设备发出任何命令** |
| 三、开输出前 | `set_output(True)` 读回 `VOLT?` **与** `CONF:VOLT:MAX?` | 不带 `confirm_enable=True` 时拒绝开启；即使他人在面板把设定值或上限改超，同样会拦住 |
| 四、运行时 | `scripts\it7321_voltage_guard.py` 监控 8808A 并切断输出 | 真实带电 10 V 输出、阈值 5 V，**52 ms 内切断** |

### 如何修改（以及为什么不该改）

上限是一个**单一常量**，带环境变量覆盖，改一处即可：

```python
# C:\english_path\github_fork\lab-equipment-mcp\src\lab_equipment_mcp\devices\itech\it7321.py
IT7321_TEST_VOLTAGE_LIMIT_V = 30.0
```

或不改代码，直接设环境变量：

```powershell
$env:LAB_EQUIPMENT_IT7321_MAX_VOLTAGE = "300"
```

`it7321_get_voltage_limit` 会报告当前生效值及其来源。两道约束保证各层一致：

* 覆盖值不得超过设备额定值（300 V）；
* `clamp_voltage_ceiling()` **拒绝把设备侧上限设得比驱动上限还高**，因此不会出现
  「驱动限 30 V、设备限 300 V」这种脱节状态。

放开该上限需要用户同意，并且必须同步提高设备侧上限。

## 手册与固件差异

实测固件 `0.16-0.22`。「手册说法」一列为编程手册的原始描述。

| 项 | 手册说法 | 实际行为 | 处理方式 |
| --- | --- | --- | --- |
| 未发 `SYST:REM` 时的控制 | 「可能会引起通讯出错」（第 9 页） | **所有设置命令被拒**并回 `-200`；查询仍正常 | `connect()` 自动发送 `SYST:REM` |
| 写命令应答 | 未描述 | 写命令静默；紧接着读回**可能返回旧值** | 读回前插入 `settle_s` 等待 |
| `VOLT:UNIT?` | 文档列为可查询 | **完全无应答** | 只写不读；指南中注明无法回读 |
| `OUTP 1`／`OUTP:STAT 1` | `<bool>`，取值 `off\|on\|0\|1` | 两种写法都接受，但需等待稳定后才可见 | 读回前等待 |
| `CONF:VOLT:MAX` | 配置上限 | **确实强制生效**：超过上限的设定值回 `120,Parameter overflowed` | 用作硬件兜底 |
| TCP 会话数 | 未说明 | 只接受一个 | 驱动独占；监控进程运行期间由监控独占 |
| **规格表的适用范围** | 第四章技术规格 | **为全系列通用表**，个别条目不适用于 IT7321（例如 `Sync Output Signal: BNC type`，而本型号后面板并无 BNC） | 判断某功能是否存在，须查该型号自己的后面板／功能章节，不能只看规格表 |
| 每条错误 | 「蜂鸣器将蜂鸣一次」（第 8 页） | 确认属实，被拒命令会响 | `drain_errors()` 清空队列 |
| **`CONF:LIST:STAR:MODE`** | 第 19 页列为可设置／可查询 | **固件完全不接受**，回 `170,Invalid command` | 不使用该命令；远程下 `LIST:STAT ENABLE` + 开输出即可运行列表 |
| **`LIST:STAT`／`SWE:STAT` 的读回** | 第 35／43 页列出查询 | 写入后立即读回**返回上一个状态**，且滞后比其它命令的 0.35 s 更久（约 1 s 才刷新）；但列表／扫描**确实已按命令执行** | 驱动改为**等待并重试直到读回与请求一致**，返回值附带 `confirmed` 标志；实测 1 s 后读回正确 |
| **长短式混用** | 第 3 页：命令字必须全用长式或全用短式 | 混用被拒：`CONF:DIMM:MODE LEADING` 与 `TRAIL` 均回 `140,Wrong type of parameter` | 驱动统一使用**长式全大写**，并在测试中钉死非法形式 |
| **`LIST:STEP:SLOP`** | 第 37 页：参数 2 是「斜率时间，浮点数，**单位：mS**」 | **实际按「秒」处理**：设 800 时 12 秒内只到 2.0%（按秒推算为 1.5%） | 驱动参数名用 `slope_ms` 并保留手册单位；使用时**不要设成几百**，否则输出几乎为零且缓慢爬升 |
| **`SWE:STAT ENABLE`** | 第 43 页只说明「设置扫描功能状态」 | **会同时关闭输出（`OUTP?` 1→0）并关闭列表模式**，必须再发 `OUTP 1` 扫描才运行 | 驱动文档与排障表注明；单独测扫描时不会遇到（那时输出本就关闭） |
| **参数表里的缩写前缀** | 第 3 页：大写字母表示缩写 | `TRAilingedge` 的短式是 **`TRA`**（不是 `TRAIL`） | 不用短式，规避前缀边界判断 |

### 与 Fluke 8808A 的接收闭环（2026-09-20）

接线：IT7321 输出火线接 8808A 红表笔（`VΩ` 端子），零线接黑表笔（`LO` 端子）；
8808A 设为 VAC、快速档。这个一致性同时确认了电压单位：**设定值与实测值 1:1，说明
设定值单位是有效值（RMS）而非峰峰值**（若为峰峰值，设定 5 V 时只会读到约 1.77 V）。

| **设定（V）** | **8808A 实测（V）** | **误差（V）** | **误差率** |
| --- | --- | --- | --- |
| 5.0 | 5.0483 | +0.0483 | +0.97% |
| 10.0 | 10.0457 | +0.0457 | +0.46% |
| 20.0 | 20.0267 | +0.0267 | +0.13% |
| 30.0 | 30.0200 | +0.0200 | +0.07% |

误差随设定值升高而收敛，各点均在 1% 以内，远优于电源自身的准确度指标。

```

    随后释放 socket（输出保持开启）
二、启动阈值 5 V 的监控进程：
    [18:09:22.558] source  VOLT?=10.0 OUTP?=1 CONF:VOLT:MAX?=30
    [18:09:22.610] TRIP    over voltage: |10.0470| > 5.0 V
    [18:09:22.610] action  OUTP 0 sent (output off)
    [18:09:22.610] action  VOLT 0 sent (setpoint dropped)
三、事后核对：VOLT? → 0.0    OUTP? → 0
```

**从读到超压到切断输出，全程 52 ms。**

### 调光削波（DPO2012B 差分探头接 CH1，2026-09-20）

输出 10 V／50 Hz，调光角 90°，示波器时基 5 ms/div。调光**必须先开启模式**
（`CONF:DIMM:MODE`），只设角度不生效。

| 模式 | 有效值（实测） | 理论 $V_p/2$ | 峰峰值 | 波形形状 |
| --- | --- | --- | --- | --- |
| `LEADINGEDGE` | **6.9999 V** | 7.07 V | 29.2 V | **先削为零，后接正弦** |
| `TRAILINGEDGE` | **7.0008 V** | 7.07 V | 28.4 V | **先接正弦，后削为零** |

两种模式导通角相同，因此**有效值一致**；**波形形状严格相反**，与前沿／后沿调光的
定义吻合。这是用采样数据比对得出的结论，不是只看命令回读。

**关于 `PHAS:STAR/END`**：手册第五章定义为「设置电源**开始**相位角」与「设置电源
**关机**相位角」，**不是裁剪稳态波形**。实测把它设为 0-180 后，连续输出的
RMS（9.8963 V）与峰峰值（28.8 V）**均无变化**——这与手册语义一致，属**正确行为**。
它作用于输出启停时刻的相位，本驱动已实现，但"启停瞬间的相位"未单独测量。

### 只有组合测试才暴露的四件事

**其一（最严重）：列表步的斜率会残留，把输出变成几乎为零。**

组合验证第一遍跑出来的列表场景**读数全部接近零**（0.057 / 0.074 / 0.093 V），
量程掉到 200 mV 档，而**发出的命令看上去完全正常**：

```
步0: {'volts': '5',  'hertz': '50', 'slope_ms': '800', ...}   ← 残留！
步1: {'volts': '10', 'hertz': '50', 'slope_ms': '800', ...}   ← 残留！
```

**根因**：驱动的 `set_list_step` 原先把 `slope_ms` 默认成 `None`，**不传就不下发
`LIST:STEP:SLOP`**，于是设备保留了上一次配置的值。前一轮探索 `SLOP` 单位时留下的
`800`（固件按**秒**解释，见下）让每步以目标值的约 0.4%/秒爬升——停留 3 秒只到
1.2%，输出看起来像坏了，而**已发送的命令里没有任何线索**。

**已修复**：`slope_ms` 默认改为 `0.0` 且**总是下发**，与 `dwell_unit` 的处理一致
（后者早已采用同样做法，理由相同）。并加了回归测试
`test_list_step_always_sends_the_slope`。

**为什么单一功能测试发现不了**：以前的列表测试每次都给全部字段赋值，恰好把残留
覆盖掉了；只有组合场景里"只改电压、其余沿用"的写法才会撞上。

**其二：使能扫描会把输出关掉。**

```
列表运行中  : 10.047 V   OUTP?=1   LIST=ENABle
>>> 使能扫描（SWE:STAT ENABLE）
切换后      : 0.403 V    OUTP?=0   LIST=DISable   SWE=ENABle
>>> 再发 OUTP 1
重开后      : 10.046 V   OUTP?=1
```

`SWE:STAT ENABLE` 会**同时关闭输出并关闭列表模式**，必须再发一次 `OUTP 1` 扫描
才会运行。手册未记载。**单独测扫描时不会遇到**，因为那时输出本来就是关的。

**其三：削波后示波器的频率读数会翻倍。**

| 波形 | 示波器频率读数 |
| --- | --- |
| 完整正弦 | 49.90 ～ 50.27 Hz（正确） |
| 前沿／后沿削波后 | **98.49 ～ 99.47 Hz**（假象） |

削波使每半周多出过零点，示波器的频率算法把它算成两倍频。**这是测量方法的假象，
不是设备故障**——同一时刻 8808A 读到 3.561 V，与理论 $V_p/2$ 吻合。用示波器测
削波波形的频率时需要留意这一点。

**其四：`LIST:STEP:SLOpe` 的单位实际是「秒」，而手册第 37 页写的是「mS」。**

单步列表 10 V，观察 12 秒：

| `SLOP` 设置 | 12 秒内达到 | 按「毫秒」预期 | 按「秒」推算 |
| --- | --- | --- | --- |
| 0 | **10.045 V（100%）** | 立即 | 立即 |
| 0.8 | **10.047 V（100%）** | 0.8 ms，立即 | 0.8 s，也快 |
| **800** | **0.200 V（2.0%）** | **0.8 s 应已满值** ✗ | 800 s → **1.5%** ✓ |

只有「按秒」能解释第三行。**把斜率设成几百会被误认为设备故障**——输出几乎为零
且在缓慢爬升（12 秒内从 0.053 爬到 0.200 V）。

### 未实机验证项

先分清三种情况：**「本型号不具备」**、**「本次范围外」**与**「具备但未测」**，
三者性质完全不同。

#### 一、本型号不具备（不是未测，是无法测）

| 功能 | 依据 |
| --- | --- |
| **BNC 复合端子**（`CONF:BNC:FUNC`） | 用户手册 2.5 节「IT7321 后面板」列出的部件只有 LAN／RS232／USB／散热风扇／AC 电源输入端子，**没有 BNC**。BNC 端子出现在 IT7322／IT7322H／IT7324／IT7324H 的后面板上。**第四章规格表中的 `Sync Output Signal: 5V, BNC type` 属于全系列通用规格，不适用本型号。** 该命令可以写入，但端子不存在，不会有任何实际作用 |
| **三相／System Bus** | 用户手册 2.1 节原文：「支持 3 台单相设备通过 System Bus 连接，实现三相交流电源功能（**IT7321 除外**）」。三相型号为 T 系列（IT7322T／IT7324T／IT7326T 等），**不存在 IT7321T**；即使有 3 台 IT7321 也无法组合 |

#### 二、本次范围外（功能存在，本次不做）

| 功能 | 说明 |
| --- | --- |
| **外部触发**（`TRIG:SOUR EXT`） | 由用户明确界定为本次不做。注意本型号的 BNC 端子不存在（见上表），因此该触发方式的物理入口需另行确认；记录为范围外而非型号限制 |
| **电流保护跳闸**（`CONF:PROT:CURR:RMS/PEAK`）与 `PROT:CLE` | 由用户界定为本次不做——**台面未接负载**，无法在受控电流下安全地制造跳闸。保护点设置与限值检查均已实现并通过单元测试，但**跳闸行为本身未实机验证** |

#### 三、具备但未测

| 功能 | 未测原因 | 可否补测 |
| --- | --- | --- |
| **电流／功率量测通道** | 电压通道已与 8808A 比对；电流与功率需要负载才能产生非零读数 | 可（需接负载） |

## 排障

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 设置命令被拒并回 `-200,Execution error` | 未进入远程模式 | 驱动在连接时自动发 `SYST:REM`；若已被切回本地，发 `it7321_set_remote` |
| 连接报 `WinError 10061` | 其他客户端占用了唯一的 TCP 会话 | 先关闭其他客户端（或监控进程） |
| 设备持续蜂鸣 | 每条错误响一声 | `it7321_get_errors` 清空、`it7321_clear_errors` 清除、`it7321_set_beeper(False)` 静音 |
| 读回显示的是上一个值 | 读命令发得太早，设备尚未稳定 | 驱动的 `settle_s` 已处理；手工写 socket 时请留约 0.5 s |
| 本该拒绝的 `VOLT 45` 被接受 | `CONF:VOLT:MAX` 仍为 300 | 调 `it7321_clamp_voltage_ceiling()` 重新压到 30 V |
| 无法访问设备地址 | 工控机没有同网段的地址 | 给工控机添加同网段地址，或在前面板 LAN 菜单中把设备改到工控机所在网段 |
| 面板按键无响应 | 远程模式会锁定除 Shift／Local／Select／On-Off 之外的所有键 | 发 `it7321_set_local`、按面板 `Local` 键，或 `it7321_disconnect` |
| **列表运行但输出几乎为零**（量程掉到 200 mV 档，命令看起来正常） | **列表步残留了旧的 `LIST:STEP:SLOP`**，而固件按**秒**解释该值（手册写毫秒）；斜率若为 800，每步只爬升约 0.4%/秒 | 驱动的 `set_list_step` 现已**总是下发** `LIST:STEP:SLOP`（默认 0），不再残留；用 `it7321_get_list_step` 核对每步的 `slope_ms` |
