# Fluke 8808A Digital Multimeter

## Manual and scope

| Item | Value |
| --- | --- |
| Manual | `8808A用户手册.pdf`, Rev. 1 (July 2007, Simplified Chinese), 94 pages |
| Manual revision string | `8808A UM R1 CHI` |
| Remote-control chapter | Chapter 4, "通过计算机接口操作万用表" (pages 4-1 .. 4-24) |
| Instrument firmware seen | `1.1r D2.0` |
| Host link | RS-232 (DB9) through a USB-to-RS-232 adapter |

The 8808A has no USB port. There is no separate programmer manual; chapter 4 of
the user manual carries the full command set (tables 4-8 .. 4-18).

## Interface and session settings

| Item | Value | Source |
| --- | --- | --- |
| Connector | DB9: pin 2 RXD, pin 3 TXD, pin 5 GND; pin 1 +5 V out, pin 9 trigger in | 3-17 table 3-4 |
| Factory settings | **9600 baud, 8 data bits, no parity, 1 stop bit**, echo off | 4-4 table 4-1 |
| Settable from the panel | baud rate (300..19200), data bits (7/8), parity, echo | 4-3 |
| Stop bits | **not a panel setting**; table 4-1 fixes them at 1 | 4-3, 4-4 |
| Named parity values | `none` (parity bit 0) and `E = even` only | 4-3, 4-4 |

| Output terminator | replies end with CR LF | 4-24 figure 4-4 |
| Case | commands are case-insensitive | 4-7 |

**Terminal settings cannot be read back over the bus.** They are front-panel
only, so `fluke8808a_connect` takes them as arguments. Defaults are the factory
values; pass the panel values when they differ.

### Protocol (verified on hardware)

Every command is acknowledged. A query sends its data first and the
acknowledgement second; a non-query sends the acknowledgement alone:

```
*IDN?    -> b'FLUKE, 8808A, <serial>, 1.1r D2.0\r\n'  then  b'=>\r\n'
FUNC1?   -> b'VDC\r\n'                               then  b'=>\r\n'
*CLS     -> b'=>\r\n'                                        (one reply)
```

Acknowledgements are `=>` (accepted), `?` (syntax error) and `!` (execution
error); the driver raises on the last two. **The acknowledgement must be read**:
leaving it buffered shifts every later reply by one. This cost a full rewrite of
the driver's protocol layer after the first hardware run — the manual's figure
4-4 shows the acknowledgement but does not spell out the two-message ordering.

## Manual versus firmware

| Item | Manual says | Instrument does | Handling |
| --- | --- | --- | --- |
| `MAXSET <value>` | Enters MAX mode and stores the value (4-18) | **Stores the value only; does not enter the mode** | Driver sends `MAX` first, then `MAXSET` |
| `MINSET <value>` | Enters MIN mode | Same as above | Driver sends `MIN` first |
| `MNMXSET <min>,<max>` | Enters MIN MAX mode | Same as above | Driver sends `MNMX` first |
| `RATE?` reply | S / M / F | `S` | Accepted as-is |
| `*IDN?` fields | 4 comma-separated fields | `FLUKE, 8808A, <serial>, 1.1r D2.0` (spaces after commas) | Parser strips per field |
| `SERIAL?` | Returns the serial number | Returns it | Driver redacts it |

`MAXSET` was found on hardware on 2026-09-20: after `MAXSET 1.0` alone, `MOD?`
returned `0`; after `MAX` it returned `2`. This is the same class of
manual-versus-firmware gap as the SDG1062X `C1:SYNC?` reply.

## Acceptance

Evidence levels follow `references/acceptance.md`. `read-back` means the
instrument was queried after the write and returned the expected state.

### Verified on hardware (2026-09-20, firmware 1.1r D2.0)

| Feature | Evidence |
| --- | --- |
| Identity and redaction | `read-back` — `FLUKE, 8808A, <redacted>, 1.1r D2.0` |
| Protocol ordering | `read-back` — raw byte capture of query data + acknowledgement |
| Function select | `read-back` — VDC, VAC, OHMS, FREQ |
| Measurement rate | `read-back` — S, M, F |
| Output format | `read-back` — 1 and 2 |
| Autorange / fixed / range | `read-back` — `AUTO?` 1/0, `RANGE1?` 2 |
| Touch hold | `read-back` — `MOD?` bit 4 |
| Relative | `read-back` — `RELSET?` `+500.000E-3` |
| Min / max / min-max | `read-back` — `MOD?` 1, 2 and 3 |
| Compare | `read-back` — `COMP?` `PASS` |
| Trigger type | `read-back` — `TRIGGER?` 1 |
| Measurement | `read-back` — `VAL?` and `MEAS1?` returned live readings |
| Remote / local | `read-back` — `REMS` and `LOCS` accepted, panel usable after |

### Not verified on hardware

| Feature | Why not |
| --- | --- |
| `*RST` | Resets the instrument; needs explicit authorisation because it discards the current setup |
| `Save` / `Call <1-6>` | Overwrites one of the six stored setups; needs explicit authorisation |
| `RWLS` / `LWLS` | Locks the front panel and requires a deliberate release step |
| External trigger types 2..5 | Requires a TTL signal on DB9 pin 9, which is not wired |
| Front-panel echo on | The panel is at the factory default (echo off); the driver strips an in-message echo but the echo-on path has not been exercised |
| RS-232 print mode | Uses the same rate table but sends readings unsolicited; not exercised |
| Status-register masking | `*ESE`, `*SRE` and `*ESR?` accepted, but no service request has been observed |
| Cold-start / power-cycle behaviour | Manual 4-4 notes baud rate, parity and echo survive power cycles; not re-tested |

## Troubleshooting

| Symptom | Check |
| --- | --- |
| No serial port in `fluke8808a_diagnose_setup` | Adapter not seated; the report lists every COM port and flags FTDI ones |
| `VI_ERROR_RSRC_NFOUND` | The COM port is not exposed by VISA; install a VISA runtime or open the resource by its exact `ASRL<n>::INSTR` name |
| Replies shifted by one | An acknowledgement was left unread; every command returns one |
| Timeouts after connecting | Terminal settings differ from the panel. There is no read-back; pass the panel values to `fluke8808a_connect` |
| Garbled or partial replies | Parity or data bits differ from the panel setting (7 data bits is a valid panel choice) |
| `?` acknowledgement | Command syntax rejected. Unparseable commands also discard the rest of the line (4-7) |
