# Siglent SDG1000X Series / SDG1062X

## Scope and evidence

This driver supports the dual-channel Siglent SDG1032X and SDG1062X. The connected
acceptance unit identified itself as an SDG1062X running firmware `1.01.01.30R1`.
Its serial number is intentionally not recorded. VISA resources, USB instance IDs, and complete
identity responses in logs should be redacted; examples use `<serial>` or `REDACTED`.

Manuals reviewed outside the repository:

- *SDG1000X Series Function/Arbitrary Waveform Generator User Manual*, revision CN01J.
- *SDG Series Function/Arbitrary Waveform Generator Programming Guide*, revision C02C,
  175 PDF pages.

The programming guide is series-wide. Commands marked for another family only, such as
SDG7000A sequence and file-management commands, are not exposed as SDG1000X tools.
Manuals are not committed because the publisher reserves copying rights.

Relevant programming-guide PDF pages: 14-16 (interfaces and LAN ports), 17-18 (SCPI
syntax), 20-35 (identity, output, waveforms, modulation, sweep), 54-62 (burst, channel
copy, ARB, Sync), and 94-95/164-168 (binary ARB transfer). The user manual pages 4,
23-38, 47-68, and 104-106 establish model capabilities and Sync behavior.

## Interfaces

| Connector | Transport / VISA form | Status | Notes |
| --- | --- | --- | --- |
| Rear USB Type-B Device | USBTMC, `USB...::INSTR` | Tested on SDG1062X | NI-VISA Runtime 15.0 and PyVISA used |
| Rear RJ45 LAN | VXI-11, `TCPIP...::inst0::INSTR` | Tested on SDG1062X | Firmware `1.01.01.30R1`; see LAN connection |
| Rear RJ45 LAN | SCPI socket, `TCPIP...::5025::SOCKET` | Tested on SDG1062X | Firmware `1.01.01.30R1`; see LAN connection |
| Optional USB-GPIB adapter | GPIB, `GPIB...::INSTR` | Implemented, untested | Optional hardware and driver |

The Type-B connector is USBTMC, not a serial COM port. The Siglent IVI driver and NI IVI
Compliance Package are not required; NI-VISA plus PyVISA and native SCPI are sufficient.

### LAN connection

The tested unit used a static LAN address, mask `255.0.0.0`, and a gateway, with DHCP off.
The host must share a subnet with the instrument before any address below can work. VISA
enumerates USB instruments but not LAN instruments, so the address is always supplied
explicitly:

```python
sdg1062x_diagnose_setup(lan_hosts=["10.0.0.230"])   # read-only *IDN? probe on port 5025
sdg1062x_connect(resource="10.0.0.230")             # expands to VXI-11
sdg1062x_connect(resource="10.0.0.230:5025")        # raw SCPI socket
```

A bare address selects VXI-11, `host:port` selects the socket, and a complete VISA resource
is used unchanged, so existing USB and GPIB resources keep working. The diagnostic probe
touches only the addresses the caller names and never sweeps a subnet.

### Interface-specific behavior

The programming guide documents the transports as separate paths, and the acceptance unit
confirmed that they are not interchangeable:

| Aspect | USB / GPIB / VXI-11 | Raw socket (5025) |
| --- | --- | --- |
| Message framing | Supplied by the transport | None; the newline terminator ends a reply |
| Binary read | One read of the declared block | Accumulated in small steps |
| Guide's own sample | `chunk_size=40*1024`, `dev.read()` | `sendall` + `sleep(1)` + `recv(4096)` loop |
| Command terminator | Library default | Every command must end with `\n` |

Guide references: section 1.2.3 (Telnet uses port 5024), section 1.2.4 (socket uses port
5025), section 5.1.4 (LabVIEW: TCP/IP needs synchronous I/O while USBTMC does not), sections
5.1.5 and 5.1.6 (Python samples set `chunk_size` in the tens of KiB), and section 5.2.1
(the socket Python sample loops on `recv(4096)`).

The backend therefore keeps the terminator configured for sockets and clears it for framed
transports, where a binary payload byte can equal the terminator, and it accumulates socket
replies in 4096-byte steps rather than requesting a whole block in one call.

## Implemented functions

- Bounded discovery, identity validation, diagnostics, capabilities, and channel state.
- Independent CH1/CH2 sine, square, ramp, pulse, noise, DC, and ARB control.
- Load, polarity, amplitude, offset, frequency, phase, duty, symmetry, pulse width,
  rise/fall time, and delay.
- AM, DSB-AM, FM, PM, PWM, ASK, FSK, PSK, sweep, burst, and guarded manual trigger.
- Rear Aux In/Out CMOS Sync source selection, guarded channel copy, built-in/user ARB
  selection, 2-16384 point signed 16-bit little-endian ARB upload, and user ARB read-back
  through `WVDT? USER,<name>`.
- Protected generic SCPI query/write for remaining documented non-destructive functions.

Waveform/mode changes require the affected output to be disabled. Enabling output requires
`confirm_enable=true`. State-changing tools use documented read-back and fail on mismatch.

## Safety restrictions

Reset, calibration, firmware update, save/recall, destructive file operations, raw output
switching, and raw channel-copy commands are blocked by default. Unsafe generic SCPI also
requires `SDG1062X_ALLOW_UNSAFE=1` and `confirm_unsafe=true`.

The driver applies conservative limits of 20 Vpp and +/-10 V peak including offset. The
actual safe voltage depends on load, cabling, and downstream equipment.

## Hardware acceptance

Automatically verified over rear USB Type-B / USBTMC:

- Windows USBTMC/VISA enumeration with Siglent VID `F4EC` and SDG1062X PID `1103`.
- Read-only identity on firmware `1.01.01.30R1`.
- Both channel outputs read back OFF before testing.
- Firmware `1.01.01.30R1` appends `.bin` when a user ARB is selected by its base name;
  the driver accepts and verifies either documented form.
- CH1 and CH2 accepted different low-amplitude basic-wave settings with read-back while
  both outputs remained OFF; the original 1 kHz, 4 Vpp sine settings were restored.
- A four-point user ARB completed binary transfer, appeared in the user waveform list,
  selected as `mcp_qa.bin`, and read back as ARB at 1 kHz/0.5 Vpp. Output remained OFF.

Physical waveform shape, amplitude, modes, and ARB are verified below with a DPO2012B
receiver MCP. Sync, external modulation and triggering, and GPIB remain untested; LAN is
covered in its own section below. Any acceptance run must restore both outputs OFF in a
`finally` path.

### DPO2012B closed-loop acceptance (2026-07-22)

Physical wiring was CH1 to DPO2012B CH1 and CH2 to DPO2012B CH2. The separately connected
AFG-2125 had communication only and remained OFF throughout. Representative receiver-MCP
results were:

- Simultaneous basic output: CH1 1 kHz/1 Vpp sine measured 1001.5 Hz/1.032 Vpp; CH2
  2.5 kHz/0.8 Vpp/30% square measured 2499.0 Hz/0.84 Vpp/30.00%.
- Simultaneous ramp/pulse: CH1 2 kHz/80% ramp measured 1998.5 Hz/1.016 Vpp; CH2
  5 kHz/20% pulse measured 5007.6 Hz/0.848 Vpp/19.96%.
- Polarity inversion changed an asymmetric pulse mean from -0.224 V to +0.255 V.
- CH1-to-CH2 copy of 3333 Hz/0.6 Vpp/0.1 V sine measured 3321.4 Hz/0.624 Vpp/0.118 V.
- AM 10 kHz/100 Hz/80% measured 10.001 kHz and 1.856 Vpp envelope span.
- FM 10 kHz with 2 kHz deviation covered approximately 8.00-12.05 kHz by cycle analysis.
- FSK detected both approximately 2 kHz and 5 kHz period populations.
- Sweep read back as 1-5 kHz/1 s; cycle analysis covered approximately 1.25-5.00 kHz.
- Five-cycle 5 kHz burst at 20 ms period measured 1.016 Vpp and about 4.2% active samples,
  close to the theoretical 5% active time.
- Simultaneous user ARBs measured CH1 500.135 Hz/1.04 Vpp and CH2 799.04 Hz/0.856 Vpp.
- Simultaneous advanced modes measured CH1 AM at 10.016 kHz/1.648 Vpp while CH2 user ARB
  measured 500.24 Hz/0.84 Vpp.
- Noise measured 0.111 V RMS with the instrument's 0.1038 V standard-deviation setting.
- DC 0.25 V measured 0.2507 V by the scope and 0.2506 V from a full-record waveform mean.
- PM, PWM, ASK, PSK, and DSB-AM produced physical output and returned their documented
  model-specific parameters. ASK/PSK/DSB-AM do not expose a generic amount parameter.

For stable display, periodic dual-channel tests used integer-related frequencies and DPO
`NORMAL` edge trigger. AM and other long-envelope displays used single-sequence acquisition.
Sweep and burst used a DPO single acquisition armed before an SDG manual trigger. This avoids
the unstable AUTO-trigger refresh seen when a carrier edge is used for a long envelope.

Sync remains SCPI-read-back only because Aux In/Out was not wired. External modulation,
external triggering, and GPIB remain physically untested.

### LAN acceptance (2026-09-18)

The same unit was moved from USB to the rear RJ45 LAN port and exercised over both
documented transports at firmware `1.01.01.30R1`. Both runs left the outputs OFF and
restored channel 1 to its captured state in a `finally` path.

| Path | Resource | Identity | Writing with read-back | 4-point ARB round trip |
| --- | --- | --- | --- | --- |
| VXI-11 | `TCPIP0::<host>::inst0::INSTR` | Passed, serial redacted | Passed | Passed |
| SCPI socket | `TCPIP0::<host>::5025::SOCKET` | Passed, serial redacted | Passed | Passed |

A full-length check then uploaded 16384 points (32768 bytes, including 344 samples whose low
byte equals the `0x0a` terminator) into the same `lanchk` slot:

| Path | Declared samples | Read back | Comparison |
| --- | ---: | ---: | --- |
| VXI-11 | 16384 | 16384 | Exact, point for point |
| SCPI socket | 16384 | - | A single large request dropped the connection |

On firmware `1.01.01.30R1`, asking VISA for the whole 32768-byte block in one socket read
took the instrument's socket service down, and both VXI-11 and the socket then refused
connections until the instrument was restarted. The backend now reads socket replies in
4096-byte steps to match the guide's loop; that path still needs re-verification on
hardware.

Results shared by both transports:

- Identity `Siglent Technologies,SDG1062X,<redacted>,1.01.01.30R1`.
- CH1 accepted 2500 Hz, 2 Vpp, 0.5 V offset square with 30% duty and 45 degree phase; every
  requested value was confirmed by read-back.
- Output load set to 50 ohm and read back as 50 ohm.
- A four-point user ARB uploaded as `lanchk` read back as
  `-32767, -16384, 16384, 32767`, matching `[-1.0, -0.5, 0.5, 1.0]` scaled by 32767. The
  reply is a bare 16-bit little-endian block with no IEEE 488.2 header, so the driver takes
  the payload length from the `LENGTH, <n>B` field and fails on a short read.
- Both outputs remained OFF, and channel 1 was restored to 1 kHz, 4 Vpp sine on a
  high-impedance load.

Not covered by this run: the analog waveform over LAN. Shape, amplitude, and timing were
established over USB with the DPO2012B and DSO-X 2012A receivers above; the LAN run
verifies the transport rather than the analog output.

Amplitude read-back depends on the configured load. Setting an amplitude while `LOAD,50` is
active and then returning the load to high impedance doubles the reported Vpp, so a restore
path must restore the load before restoring the amplitude.

### Agilent/Keysight DSO-X 2012A receiver acceptance (2026-07-26)

The second receiver setup connected SDG1062X CH1 to DSO-X 2012A CH1 and SDG1062X CH2 to
DSO-X 2012A CH2. Both SDG outputs were configured as low-amplitude sine waves and the
DSO-X acquired each channel through its USBTMC MCP session:

| Path | SDG setting | DSO-X measured frequency | DSO-X measured Vpp | Sampled waveform Vpp |
| --- | --- | ---: | ---: | ---: |
| CH1 -> CH1 | 1 kHz, 0.5 Vpp, 0 V | 1000.0 Hz | 0.52 V | 0.518 V |
| CH2 -> CH2 | 2 kHz, 0.5 Vpp, 0 V | 2000.0 Hz | 0.52 V | 0.515 V |

This is automated receiver-MCP closed-loop evidence, not generator SCPI read-back alone.
The run also exposed and fixed DSO-X ASCII waveform block parsing: the instrument returns
an IEEE 488.2 block containing already-scaled floating-point values. Both SDG outputs were
disabled and the original SDG and DSO-X settings were restored in the cleanup path.

## Troubleshooting

- For Code 43 / invalid configuration descriptor, bypass USB hubs, use a known data cable,
  and connect directly to the computer.
- If Windows sees the device but VISA does not, close EasyWave/NI-MAX sessions and reconnect.
- Install NI-VISA Runtime or another USBTMC-capable VISA runtime; the IVI package is optional.
- For LAN, configure and verify the IP, then use VXI-11 or socket port 5025.
- VISA does not list LAN instruments, so `sdg1062x_diagnose_setup` and `sdg1062x_connect`
  need the address passed in explicitly.
- A host mask such as `/32` leaves the interface unable to reach any other address: no
  on-link route matches and there is no gateway, so the packet is dropped locally. Widen the
  mask or add a second host address on the instrument subnet; the instrument itself cannot
  compensate.
- A LAN socket that answers a read-only `*IDN?` but times out on a binary query usually
  means the read terminator was cleared on a transport that has no other end-of-message
  signal.
- Reading a whole waveform block from a raw socket in one large VISA request can take the
  instrument's socket service down. Read in 4096-byte steps, as the guide's socket sample does.
- If both LAN services stop answering while `ping` and port 111 still respond, the
  instrument's network services need a restart.

```text
With CH2 output off, configure a 1 kHz, 1 Vpp sine at 0 V offset, read it back, and ask
```
